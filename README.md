# تطبيق قضاء الصلوات — Qada Prayer Tracker

> *"وَأَقِمِ الصَّلَاةَ طَرَفَيِ النَّهَارِ وَزُلَفًا مِّنَ اللَّيْلِ ۚ إِنَّ الْحَسَنَاتِ يُذْهِبْنَ السَّيِّئَاتِ"*

---

## ما هذا التطبيق؟

**تطبيق قضاء الصلوات** هو رفيق رقمي هادئ يُعين المسلم على تنظيم رحلة قضاء الصلوات الفائتة وتتبعها يوماً بيوم. صُمِّم بروح من التشجيع والرحمة، بعيداً عن الإحساس بالإثقال أو اليأس، فكل صلاة تُقضى هي خطوة للأمام وإزاحة لدَين من الذمة.

---

## المشكلة التي يحلّها

كثير من المسلمين يمرون بمرحلة في حياتهم يُهملون فيها الصلاة، ثم يتوبون ويعودون إلى الالتزام. في هذه اللحظة تظهر معضلة حقيقية:

- **الكم الهائل** — قد يصل عدد الصلوات الفائتة إلى آلاف الصلوات مما يُسبب الإحباط ويجعل البداية مستحيلة في الذهن.
- **الفوضى والنسيان** — بلا نظام واضح يسهل التوقف أو الانقطاع بعد أيام أو أسابيع.
- **الجهل بالحكم الشرعي** — بعض الناس لا يعرف أصلاً أقوال العلماء في المسألة، فيتردد هل يبدأ أم لا.
- **غياب الدافع** — عدم رؤية التقدم الفعلي يُضعف الاستمرار.

يأتي هذا التطبيق ليُعالج هذه المعضلة بأداة عملية ومُحفِّزة.

---

## كيف يعمل التطبيق؟

### ١. إعداد الخطة الشخصية

يبدأ المستخدم بمعالج إعداد خطوة بخطوة يجمع:

- **تاريخ الميلاد** وتاريخ البلوغ (بداية التكليف الشرعي).
- **تاريخ الالتزام** — اليوم الذي بدأ فيه المستخدم المحافظة على الصلاة فعلياً.
- **تقدير الأيام الفائتة** — إما بإدخال سنوات/شهور/أيام بشكل تفصيلي، أو بإدخال عدد الأيام مباشرةً. يحتسب التطبيق تلقائياً المدة بين البلوغ والالتزام كمرجع مساعد.
- **الهدف اليومي** — كم يوماً من القضاء (كل يوم = ٥ صلوات) سيلتزم المستخدم بقضائه كل يوم. يتراوح الخيار بين يوم واحد للمبتدئين وخمسة أيام للراغبين في الإسراع.

على أساس هذه البيانات يحسب التطبيق تاريخاً تقديرياً لإتمام القضاء، مما يمنح المستخدم هدفاً زمنياً ملموساً.

### ٢. التسجيل اليومي

الصفحة الرئيسية تعرض **ورد اليوم** — قائمة الصلوات الخمس مع إمكانية تسجيل عدد ما قُضي من كل صلاة. يمكن تسجيل أكثر من صلاة من نفس النوع في اليوم الواحد (مثلاً: ثلاث صلوات فجر قضاءً). يُتيح التطبيق أيضاً تسجيل صلوات لأيام سابقة إن نسي المستخدم التسجيل في وقته.

### ٣. متابعة التقدم

يعرض التطبيق لوحة تقدم شاملة تشمل:

- **شريط تقدم** يُظهر نسبة ما أنجز من إجمالي الصلوات.
- **عدد الأيام المكافئة المنجزة** وعدد الصلوات المتبقية.
- **تاريخ الإتمام المتوقع** مُحدَّث باستمرار بناءً على ما تُقضى.
- **تفصيل التقدم لكل صلاة** (فجر، ظهر، عصر، مغرب، عشاء) منفردةً.
- **سلسلة المواظبة** — عدد الأيام المتتالية التي أتمّ فيها المستخدم هدفه اليومي.
- **آخر الصلوات المقضية** — قائمة بأحدث ما سُجِّل للتحفيز.

### ٤. التقويم الشهري

صفحة التقويم تعرض خريطة حرارية شهرية تُلوّن كل يوم بحسب نسبة الإنجاز فيه — من أخضر قاتم لمن أتمّ هدفه وأكثر، إلى رمادي لمن لم يُسجّل شيئاً. النقر على أي يوم يفتح نافذة لتعديل سجلات ذلك اليوم.

### ٥. الدليل الشرعي

صفحة الدليل تُقدم للمستخدم الإطار الشرعي لمسألة القضاء بصياغة واضحة وميسّرة، في شكلين يختار بينهما:

- **سؤال وجواب** — أسئلة شائعة تُفتح وتُغلق للاطلاع على ما يهم المستخدم فقط.
- **مقالة كاملة** — عرض موسّع منظم بأقسام متتالية.

يشمل الدليل: الحكم الشرعي عند الجمهور، أقوال العلماء المعاصرين كابن باز وابن عثيمين، أقوال الأئمة الأربعة، الخلاف العلمي في المسألة، وأدلة قرآنية وحديثية. كل ذلك بهدف تقوية قناعة المستخدم وإزالة التردد.

## الفلسفة التصميمية

| المبدأ | التجسيد |
|---|---|
| **الاستمرارية لا الكمالية** | الهدف اليومي قابل للتعديل في أي وقت |
| **التحفيز المرئي** | الخريطة الحرارية وسلسلة المواظبة لإدامة الزخم |
| **الخصوصية** | البيانات تُحفظ محلياً، لا حسابات ولا خوادم خارجية |

---

## الجمهور المستهدف

- كل مسلم ومسلمة تاب إلى الله وعزم على قضاء ما فاته من الصلوات.
- من يريد نظاماً يساعده على الاستمرار دون أن يشعر بثقل العدد الكبير.
- من يحتاج إلى إطار شرعي يُرسّخ نيته ويُجيب على تساؤلاته قبل البدء.

---

## المزايا التقنية الجوهرية

- **عربي أولاً** — الواجهة بالكامل بالعربية مع دعم الأرقام العربية  (٠ ١ ٢ ...) والتحويل بزر واحد.
- **ليلي/نهاري** — يدعم الوضع الداكن والفاتح مع حفظ التفضيل.
- **سريع وخفيف** — بلا تحميل بطيء ولا اشتراطات تسجيل دخول.

## Guide développeur

Cette section explique comment installer le projet en local, faire des modifications, puis proposer les changements avec une Pull Request.

### Prérequis

Avant de commencer, installez :

- Flutter SDK compatible avec Dart `>=3.2.0 <4.0.0`
- Android Studio ou VS Code avec les extensions Flutter/Dart
- Git
- Un émulateur Android/iOS ou un appareil physique connecté

Vérifiez que votre environnement Flutter est prêt :

```bash
flutter doctor
```

### Installation locale

Clonez le projet :

```bash
git clone https://github.com/Marindo-12/qada_tracker.git
cd qada_tracker
```

Installez les dépendances :

```bash
flutter pub get
```

Si vous modifiez les tables Drift, les DAO, ou les fichiers liés à la base de données, régénérez les fichiers générés :

```bash
dart run build_runner build --delete-conflicting-outputs
```

Lancez l'application :

```bash
flutter run
```

### Structure du projet

- `lib/core` : configuration globale, navigation, thème, base de données et utilitaires.
- `lib/features` : écrans et logique métier organisés par fonctionnalité.
- `lib/shared` : composants, providers et éléments réutilisables.
- `assets` : images, icônes, polices et ressources statiques.
- `test` : tests automatisés.

### Bonnes pratiques de contribution

Avant de proposer une modification :

- Créez une branche dédiée :

```bash
git checkout -b feature/nom-de-la-fonctionnalite
```

- Gardez les changements liés au même objectif dans la même Pull Request.
- Respectez le style existant du projet.
- N'ajoutez pas de refactoring non lié à votre changement.
- Testez l'application sur au moins un appareil ou émulateur.
- Mettez à jour le README si votre changement ajoute une nouvelle étape d'installation, une dépendance ou un comportement important.

### Vérifications recommandées

Avant d'ouvrir une Pull Request, lancez :

```bash
flutter analyze
flutter test
```

Si vous avez modifié le code généré par Drift, vérifiez aussi que les fichiers générés sont bien à jour après `build_runner`.

### Ouvrir une Pull Request

1. Commitez vos changements avec un message clair :

```bash
git add .
git commit -m "Describe your change"
```

2. Poussez votre branche :

```bash
git push origin feature/nom-de-la-fonctionnalite
```

3. Ouvrez une Pull Request depuis GitHub vers la branche principale du projet.
4. Dans la description de la Pull Request, indiquez :

- Le problème résolu ou la fonctionnalité ajoutée.
- Les fichiers ou écrans principaux modifiés.
- Les tests effectués.
- Les captures d'écran si le changement touche l'interface.

### Notes importantes

- Les données utilisateur sont stockées localement.
- Les assets utilisés dans le code doivent être déclarés dans `pubspec.yaml`.
- Après l'ajout d'un nouvel asset, relancez l'application pour que Flutter le prenne en compte.
- Pour les changements liés à la base de données, vérifiez les migrations et les fichiers générés avant d'ouvrir la Pull Request.
